# 通用奇幻伙伴：生成前锁定的交付规则 v3

生图提供角色设计与姿势，后续固定程序只做裁切、去底、统一等比定位、主色提取与配置装配。不针对物种、名字、照片年龄写分支。不保证模型任意输出都合格：错误格式拒绝并保留原图，不能为让某一张通过而移动切线、放宽边界或偷偷AI修图。

新增固定画框流程 `npm run pet:generate:guided`，见 [GUIDED-PET-LAYOUT.md](GUIDED-PET-LAYOUT.md)。它保留本合同的最终游戏图集、动作顺序、配色与入库规则，但模型收到的是预画的三格/九格模板：检查辅助区及完整轮廓后去掉辅助线，最终留白由程序补齐。该流程的模型输入规范以 `guided-windows-v7` 为准，不同时要求模型满足下文旧直接生图的64/96px留白。设计输入为模板、用户图、画风参考；动作输入为模板与对应阶段定稿。技能格的外放特效贴边只标记复核，角色本体仍须完整。

## 固定提示词与原创替代

当前提示词版本为 `generic-original-v2`，设计全文见 [gpt-pet-design.txt](prompts/gpt-pet-design.txt)，三个动作模板见 [阶段1](prompts/gpt-pet-stage-1.txt)、[阶段2](prompts/gpt-pet-stage-2.txt)、[阶段3](prompts/gpt-pet-stage-3.txt)。这些文本由 `scripts/pet-gpt-prompts.cjs` 导出；动作阅读版以绿底展示，实际底色仍由固定算法选择。以后只更换图片，不根据具体动物、年龄或已有角色重写文案；一至三张用户图统一装入图1，图2固定作为画风参考，因此单图、多图实际设计提示词逐字相同。

- 清楚显示自然主体的照片，按常规流程保留自然外貌、可用的辨识特征及气质，模型自行判断对应成长阶段；照片中的现成角色玩偶、印花等除外。
- 插画、卡通、游戏角色、虚拟形象或无法确信是自然照片的输入，默认只取一至两个宽泛主题，从第一阶段就重新构思独立轮廓、头脸、身体结构、材质、配色和进化路线，不再依赖模型认出具体角色名。此保守默认也会重构用户自有插画；当前没有授权证明分支。不以让人认出原角色为目标，不靠改名、换色或加配饰声称消除风险。原创分支的相似度要求服从新身份，不能被后文“保留颜色/配饰”覆盖。
- 不适宜直接表现的内容予以舍弃；只有可以独立构思友好、全年龄角色时才采用中性主题继续创作，仍无法符合服务规则就停止。提示词不要求突破审核，也不保证所有输入都能成功或获得商用授权。
- 原创选择在三阶段设计时完成。动作只沿用定稿，不能在不同格子或不同阶段另造身份；定稿本身无法继续时停止，不能用不一致角色填满图集。

这是一套预先写入的创作约束，**不是版权识别器或法律意见，也不是接口拦截后的自动绕过逻辑**。模型可能未识别已有角色，输入也可能在模型理解提示词之前就被拦截。当前客户端保存终止错误，不自动换模型、降低审核或改写提示词反复提交。格式检查不能证明版权、相似度或审美合格。错误处理参照 [OpenAI 图片生成说明](https://developers.openai.com/api/docs/guides/image-generation#handling-blocked-requests-and-other-errors)。

## 图片合同（保持 v3）

1. 设定图3072×1024，三列各1024，四边留64像素；模型自行判断输入是什么及处于哪个阶段，不默认幼年。三阶段以可爱→灵动→帅气的奇幻能力觉醒串联。半写实只约束材质与画法，允许幻想器官、明显轮廓变化。暹罗猫仅参考画风。
2. 动作图每阶段1536×1536，3×3固定512格。合同安全区至少留32像素，当前提示词进一步要求96像素留白（中央320×320）以降低模型画满格子的概率，后续转换门槛不放宽。顺序为待机、眨眼、招呼、互动、进食、思考、睡眠、跳跃、技能。动作输入只用对应定稿，不再传猫的动作图。食物与吃法自由，只有进食格携带食物。
3. 全套动作比例统一、全身完整。生物本体的翼、尾火等保留；背景与远处光环用程序绘制。锁定设计后按像素冲突最少原则选绿/蓝/红抠图底色，再冻结进任务合同，不在生成后换色猜测。
4. 输入先做通用等比标准化：设计严格3:1且宽至少1536px，动作严格1:1且宽至少768px，任一边不超过8192px。符合比例的PNG统一等比缩放到上述标准画布，再按固定格切片；比例错误、分辨率不足、空格、背景不能去除、主体贴边即拒绝。该规则经用户允许后在动作生成前冻结；放大不等于新增细节，不移动切线、不使用AI修图。原图提示词要求32px留白；已有去底硬门槛保持为每边至少12px、外侧4px至少98%透明、画布至少15%被去底，不因个案调整。每阶段九姿势共用一个等比缩放因子，最大包围框放入416×400，水平居中、足底448；因此最终格左右/顶部至少48px、底部64px透明留白。不把卧睡姿势放大成站立高度，不套猫的逐格轮廓。
5. 对三阶段透明待机帧采样不透明像素，24色相桶按饱和度加权提取主色；忽略透明底和近白/近黑对色相的干扰。背景取邻近色、降低饱和度并与主体保持明暗分离；特效和UI取同色系。纯灰主体采用低饱和蓝灰。结果保存为v2颜色数据，重开不随机；旧v1宠物外观保持。
6. 导出标准template-v1图片包，仍由共享播放器加载，不生成角色专属代码。新ID表示新宠物，已有ID保持成长；生成完成免费拥有且显示在列表前部，最新完成排第一。普通内置伙伴另行200积分兑换，首次免费初始领养保持。

规则源：`scripts/pet-gpt-prompts.cjs` 的CONTRACT；标准化：`scripts/pet-normalize.cjs`；转换：`scripts/pet-fantasy-assemble.cjs`；配色：`wechat/runtime/pet-colors.js`。离线测试先验证长条、有翼、卧睡形态、绿色主体/蓝底、不同分辨率同宽高比、重跑一致以及坏比例/空格拒绝，再提交本轮模型任务。真实输出仍需检视身份和动作语义，像素规则不能判断每种生物的解剖和审美。

## 旧直接生图入口的执行与恢复

下面保留旧直接生图流程的命令；默认新任务使用透明模板与容错分格，命令见 [ALPHA-PET-PIPELINE.md](ALPHA-PET-PIPELINE.md)。灰底固定模板记录见 [GUIDED-PET-LAYOUT.md](GUIDED-PET-LAYOUT.md)。

```sh
# 先准备提示词、输入参考与规则哈希，不发付费请求。
npm run pet:generate:direct -- --out artifacts/new-job --photos /path/to/input.png \
  --id custom-new-job --name '专属伙伴'
# 添加--submit提交；顺序处理各阶段，pending时不再提交下一阶段，隔一段时间运行相同命令。
# 支持1—3张同一主体的图片，--photos用逗号分隔，多图先确定性拼为身份参考。
npm run pet:generate:direct -- --out artifacts/new-job --photos /path/to/input.png \
  --id custom-new-job --name '专属伙伴' --submit
# 已有完整四张图时，转换无需网络或凭据。
npm run pet:assemble:fantasy -- --in artifacts/new-job --id custom-new-job --name '专属伙伴'
```

若已有选定的三阶段设定图，首次准备时加 `--design-image /path/to/design.png`，后续恢复也保留该参数；流水线冻结该图哈希，跳过设计请求，仅生成三张动作图。也可用 `--action-images '/path/stage1.png,,/path/stage3.png'` 固定已有合格阶段，三项依次对应阶段1/2/3，空项才请求生成；所有复用图片仍通过相同门槛，来源哈希进任务记录。输入、比例或规则改变须使用新任务目录，旧任务记录保留。

`recipe.json` 在首次提交前固定照片、提示词、标准化、转换器、去底与配色算法的哈希；修改输入或规则会拒绝恢复。`contract.json` 在动作提交前固定排版与底色。一个任务内顺序提交，当前阶段pending时不会提交下一阶段，降低并发限流风险。设计或动作不符合标准化条件、图集裁切失败时停止，保留失败文件，不自动换规则或追加付费生成。`candidate` 尚未完整产出前不可加入游戏目录列表。完成的任务保存异步任务号，恢复仅查询、下载或离线装配；`normalization.json` 和 `quality.json` 记录原始分辨率、目标尺寸与缩放倍数。
