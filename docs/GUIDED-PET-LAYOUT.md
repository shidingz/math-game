# 固定画框与程序留白 v7

目标：让模型在预先画好的区域里填图，减少三阶段设计和动作图越格。完整流程为 `pet-guided-pipeline.cjs`，生成前冻结规则，依次生成三阶段设定及三个阶段的九动作图，再接入既有图集转换器。是否已完成某次实测，见任务目录的 `pipeline-status.json`，不能把离线测试通过当作真实生图成功。

模型的可绘制区域与游戏最终留白分开。内层框只引导绘制，程序按外层固定格裁切，保留轻微跨过内框的角色像素，再按每阶段共同的比例缩放、补成标准透明格。不要求模型精确画出最终素材所需的几十像素留白。按用户要求，动作可绘制框从384×384扩大为416×416；技能特效贴框不直接判废，关键是角色本体完整。

## 输入职责与提示词

设计时，图1是待填充的三格模板，图2是用户单张或多张输入组成的参考板，图3只提供美术风格。动作时，图1是九格模板，图2是对应阶段定稿。模板作为第一个编辑输入，而不是最后附带的小图。

提示词先说明“直接填图1”，再分配各参考的职责、规定画框位置、陈述角色设计内容，最后检查完整性。不让模型去除辅助线或自行重新裁图。灰色辅助区与深色分界线必须保留在原位置，程序只在检查通过后按固定坐标剔除。框内不画辅助线，避免线条混进毛发或翅膀。

复用 `generic-original-v2` 的通用主体与原创分支，不按当前示例编写动物特征。完整文本见 [设计](prompts/gpt-pet-guided-design.txt) 和 [动作示例](prompts/gpt-pet-guided-stage-1.txt)。动作只替换固定阶段编号与抠图底色。

## 生成前冻结的规则

| 项目 | 三阶段设计 | 每阶段动作 |
| --- | --- | --- |
| 画布 | 3072×1024 | 1536×1536 |
| 排列 | 3列×1行 | 3列×3行 |
| 原始格 | 1024×1024 | 512×512 |
| 固定画框 | 格内(128,128)，768×768 | 格内(48,48)，416×416 |
| 提示词要求框内留白 | 轮廓与框边之间有连续白色背景 | 轮廓与框边之间有连续纯色背景 |
| 内框边缘检查 | 小于1px间隙时标记视觉检查 | 小于1px间隙时标记视觉检查，不直接裁掉角色 |
| 画框底色 | 白色 | 预先选择的红、绿或蓝抠图色 |

规则源是 `scripts/pet-layout-guide.cjs` 的 `LAYOUT`，写入每个任务的recipe，连同提示词、检查器和转换器哈希一起在请求前固定。允许既有同宽高比标准化，不允许改切线去寻找角色。

1. 先检查PNG、宽高比与最低分辨率，按既有通用规则等比标准化。
2. 检查灰色辅助区，允许每通道42以内的渲染差异，超差像素超过辅助区1%则拒绝。固定画框外侧3px允许已知框内背景色与灰底混合的抗锯齿；分界线固定位置的8px范围内允许深浅灰线条及其混色。两者均不移动裁切位置，也不接受任意角色颜色。这是在容忍最终会丢弃的辅助线误差，不改变角色完整性的要求。
3. 内框中清除从边缘连通的灰色辅助背景，最多进入16px；遇到纯抠图色即停止，不穿过纯色间隔去删除同色角色细节。若灰色连通区深达16px边界则拒绝，以免误认灰色主体。外侧辅助区只移除已知底色，深色分界线仅在固定格边缘8px范围内清除。**不再直接裁掉内框最外3px**；角色像素稍微跨内框时仍原位保留。
4. 拒绝空框；任何内框贴边均记录 `edgeReview:true`，不自动认定角色缺损，试装前人工确认角色本体完整。不能用像素算法假装区分火焰、毛发、尾巴或翅膀。白色主体细节、语义、解剖及文字仍需视觉检查，几何通过不等于全面合格。
5. 实际裁切始终按外层1024/512固定格进行，不根据角色改变切线。清理辅助色后，动作仍由既有转换器检查外层边界和透明度、去底；每阶段九格使用共同等比因子，将最大包围框放入416×400，水平居中、底部对齐到448，输出512×512格。因此最终左右/顶部至少48px、底部64px透明留白；睡眠等低矮姿势不单独放大。程序不补画肢体、不修复缺失的身体。

模板是普通视觉输入。本实验没有发送API mask字段，不应称为蒙版局部重绘。OpenAI官方文档说明，甚至mask本身也属于模型引导，未承诺精确遵守边界；302.AI中转接口的实际表现需另测：[图片编辑与遮罩](https://developers.openai.com/api/docs/guides/image-generation#edit-an-image-using-a-mask)。

## 执行

```sh
npm run pet:generate:guided -- --out artifacts/new-guided-pet --photos /path/to/photo.png \
  --id custom-new-guided --name '专属伙伴'
# 先检查模板、提示词与recipe，再提交。记录taskId后只查询同一个任务。
npm run pet:generate:guided -- --out artifacts/new-guided-pet --photos /path/to/photo.png \
  --id custom-new-guided --name '专属伙伴' --submit --stop-after design
# 设计通过并检查后，去掉--stop-after逐阶段完成；也可指定stage1、stage2、stage3暂停检查。
# pending时稍后运行相同命令。失败不更改规则、不自动再次付费。
# 已有设定可在首次准备时添加--design-image /path/to/design.png，后续恢复也保留。
# 图片哈希在recipe锁定，仍通过设定排版检查，但不再次请求设计生图。
# 已有同规范动作可用--action-images '/path/stage1.png,,/path/stage3.png'复用。
# 三个位置必须保留，空项才生成；复用原图仍通过同一套固定检查。
```

设定通过后保存在 `design-clean/`，每阶段通过后保存在 `stageN-clean/` 和 `processed/stageN/`。三个阶段全部通过才生成 `candidate/pet.json`、三张透明动作图集与缩略图。`pipeline-status.json` 记录完成位置、实际请求次数和任务号；失败与重试的原始任务目录保留。缓存恢复不重复提交已完成的请求。纯规则转换不调用AI。

如果模板仍频繁失败，后续更稳妥的实验是“一次只生成一个阶段/姿势，程序拼图”，或改为带明确位置的局部编辑。前者消除跨格问题，但增加请求数和身份一致性管理；不能仅凭一张成功图片承诺模板适用于所有用户输入。

## 历史实验 v1（2026-09-16）

`artifacts/guided-layout-study-v1`：一次302.AI请求，输入为模板＋同一用户图＋固定美术参考，输出2172×724。模型保留了三个画框、灰色间隔和分界线，视觉上角色都留在各自画框里；也重新设计了不同于原输入的幻想主体。这只是单次观察，不能作为成功率或权利判断。

程序通过宽高比标准化和辅助区检查，随后在第一个画框停止：底部31px，小于预先固定的32px。独立只读像素诊断显示三阶段最小留白分别为31、14、4px（未做连通噪声过滤，详细见raw-pixel-diagnostic.json）。因此完整结果仍是 `layout-rejected`，未生成clean文件、未制作动作或导入游戏，未为了当前图调整阈值。

这次改善的是“画进正确格子”，尚未解决“模型倾向画满可见白框”。后续应把“可绘制区”和“最终素材留白”分开：模板给出更小的明确可绘制区域，程序在验证主体完整后添加统一外围留白；所有新阈值都必须先定义并用新生成任务验证。若仍不稳定，采用单角色/单动作生成后程序拼图作为兜底，不能依靠无限加长提示词。

当前8项相关离线测试覆盖上述条件，包括辅助线偏移不改变产物、灰色边缘清理不越过纯色间隔、深灰区域拒绝、设定与动作复用、缓存恢复不重复请求。这些检查验证程序，不证明真实模型每次都能守住格式。
